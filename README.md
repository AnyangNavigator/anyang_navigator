## 프로젝트 한 줄 요약

안양시는 계획도시 동안구와 원도심 만안구가 공존하는 이중 도시구조를 갖고 있고, 이는 2025년 안양시 사회조사 실측 데이터로 뒷받침된다. 이 서비스는 안양시 공공데이터를 구 단위·행정동 단위로 재구성해 격차를 진단하고, "특정 지역에 특정 시설을 투입하면 격차가 얼마나 줄어드는지" 시뮬레이션까지 제공하는 균형발전 의사결정 지원 도구다.

## ⚠️ 가장 먼저 읽을 것: 데이터 관련 주의사항

1. **집계 단위가 두 가지로 다르다.** 2025 안양시 사회조사(`data/survey_*.csv`)는 **만안구/동안구 딱 2개 구간까지만** 집계돼 있다. 안양1동, 평촌동 같은 개별 행정동(32개) 단위 만족도 데이터는 존재하지 않는다. 반면 인구·주차장·복지시설 같은 시설 현황 데이터는 행정동(32개) 단위로 존재한다(`data/population_by_dong.csv`). **UI에서 이 둘을 절대 섞어서 "동별 만족도"인 것처럼 보여주면 안 된다.** 사용자가 동을 고르면 → 그 동이 속한 구의 사회조사 평균(구 단위) + 그 동 자체의 시설밀도(동 단위)를 **레이블을 명확히 구분해서** 같이 보여줄 것.
2. **자유 서술형(주관식) 텍스트 데이터는 없다.** 16-3번 문항("불만족 이유")은 사전 정의된 객관식 선택지에 대한 응답 비율일 뿐, NLP 감성분석/토픽모델링을 적용할 원문 텍스트가 없다. 이 데이터로 "자유응답 텍스트 분석" 기능은 만들지 말 것.
3. **`reference/` 폴더의 두 docx 파일 중 `_제출서류초안.docx`에는 16-3번 문항 수치 오류가 있다.** (엑셀을 사람이 눈으로 읽다가 컬럼이 하나 밀려서 생긴 오류) 숫자는 항상 `data/` 폴더의 CSV를 기준으로 삼을 것. docx는 서술/맥락 참고용으로만 쓸 것.
4. `reference/`의 원본 xlsx 두 개는 각각 60~70개 문항의 방대한 통계표다. 이번 프로젝트에 필요한 건 이미 `data/`에 정제해 뽑아놨지만, 혹시 다른 문항(예: 지역안전도, 청년정책 등)이 더 필요해지면 원본 xlsx에서 직접 추가로 뽑아 쓸 수 있다.

## 검증된 핵심 데이터 (사업계획서에 실제로 인용된 수치)

- **주차장 불만족(체감)**: 만안구 29.4% ≈ 동안구 30.0% → 지금 당장의 불편함은 비슷함
- **공영주차시설 향후 필요 응답**: 만안구 41.7% vs 동안구 26.5% → **격차 +15.2%p**
- **보건의료시설 향후 필요 응답**: 만안구 39.4% vs 동안구 20.6% → **격차 +18.8%p**
- **"주차시설 부족" 때문에 지역에 불만족한다는 응답**: 만안구 22.0% vs 동안구 17.5%
- **"편의시설 부족" 때문에 불만족**: 만안구 27.5% vs 동안구 16.1% (격차 가장 큰 항목)
- **"교통이 불편해서" 불만족**: 만안구 13.6% vs 동안구 19.2% → 여기는 반대로 동안구가 더 높음 (격차가 항상 만안구에 불리한 방향은 아니라는 균형 잡힌 근거)

즉 결론: **"지금 불편한 정도는 비슷하지만, 앞으로 뭐가 더 필요하냐고 물으면 만안구가 훨씬 목마르다"**는 게 이 프로젝트의 핵심 근거.

## 실행 방법

Node.js가 설치되어 있지 않은 환경이라 프론트엔드는 React 대신 **FastAPI + Jinja2 + Tailwind CDN** 단일 Python 스택으로 구현했습니다. 별도 빌드 과정 없이 바로 실행됩니다.

```bash
pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

브라우저에서 http://127.0.0.1:8000/dashboard 접속. LLM 리포트는 `OPENAI_API_KEY` 환경변수가 있으면 실제 LLM을 호출하고, 없으면 구조화 데이터 기반 규칙 리포트로 자동 폴백합니다(항상 작동 보장).

지도는 카카오맵 대신 **네이버 지도(NCP Maps) Dynamic Map**으로 구현했습니다. 기본 Client ID는 [main.py](app/main.py)에 하드코딩돼 있고(도메인 화이트리스트로 보호되는 공개 키라 노출돼도 무방), 배포 도메인이 바뀌면 `NAVER_MAP_CLIENT_ID` 환경변수로 덮어쓰면 됩니다. NCP 콘솔의 해당 애플리케이션에 **Dynamic Map**이 켜져 있어야 하고, Web 서비스 URL에 실제 접속 도메인(로컬 `http://127.0.0.1:8000` 포함)이 등록돼 있어야 합니다. (이전에는 동 이름을 좌표로 바꾸는 Geocoding도 필요했지만, 실제 행정동 경계 GeoJSON을 직접 서빙하는 방식으로 바뀌면서 더 이상 필요하지 않습니다.)

행정동 경계 GeoJSON(`data/anyang_dong_boundaries.geojson`)은 [vuski/admdongkor](https://github.com/vuski/admdongkor) 공개 데이터에서 `scripts/extract_anyang_geojson.py`로 추출한 것입니다. 원본 소스가 갱신되어 동 이름이 바뀌면 이 스크립트를 다시 돌리면 됩니다.

## 배포 (Render)

배포 설정은 `render.yaml`(Blueprint) + `runtime.txt`(Python 3.12 고정)로 저장소에 포함돼 있습니다.

1. [render.com](https://render.com) → **New → Blueprint** → 이 저장소 연결 → `render.yaml`이 자동 인식됨
2. 서비스 환경변수 설정 (Render 대시보드):
   - `OPENAI_API_KEY` — 선택. 없으면 규칙 기반 리포트로 폴백(앱은 정상 작동)
   - `NAVER_MAP_CLIENT_ID` — 선택. 배포 도메인이 기본 하드코딩 키의 화이트리스트 밖이면 설정
3. **NCP 콘솔** → 네이버 지도 애플리케이션 → Web 서비스 URL에 **배포된 `*.onrender.com` 도메인 추가** (안 하면 지도 타일이 안 뜸)
4. 헬스체크 경로는 `/healthz` (데이터 로드까지 확인). 배포 후 `/dashboard`, `/simulator`, `/api/dong-boundaries`, 리포트 생성, 챗봇을 육안 스모크 확인
5. ⚠️ **공개검증 기간(수상 후보작 10일 이상 온라인 공개) 동안 서비스를 내리지 말 것.** Render 무료 플랜은 15분 유휴 시 슬립 → 첫 요청이 느릴 수 있음(기능엔 지장 없음)

로컬에서 배포와 동일하게 띄우려면: `uvicorn app.main:app --host 0.0.0.0 --port 8000`
